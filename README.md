# 劳动收入组成 · 桑基图

一张图看清「钱从哪来、被谁拿走、最后到你手里多少」——30 种真实用工形态，从公务员到众包骑手，从大厂 P7 到建筑包工头，同一个滑杆，六座城市。

**在线地址：<https://dao1023.github.io/labor-income-sankey/>**

零依赖、单文件 HTML，双击 `docs/index.html` 即可离线打开。

## 怎么看

左侧选案例，中间是桑基图：

- **个人视角**：收入构成 → 税前应发 → 个人扣缴 → 去向（到手 / 公积金账户 / 年金账户 / 社保统筹 / 医保统筹 / 国库 / 平台中介）
- **单位成本视角**：额外加一条干流（单位附加成本 → 单位缴纳 → 单位五险一金分项 → 对应统筹池），左右总额都等于用工总成本

拖动薪资滑杆实时重算；可切换城市（沪 / 京 / 深 / 穗 / 杭 / 蓉）、专项附加扣除、公积金比例、年终奖计税方式。

## 数据口径（三条免责）

1. **近似建模**：每个案例用「法律关系 × 社保缴费主体 × 税目 × 波动来源」四个变量描出典型画像，不是某一家的真实工资条；区间取行业内常见值。
2. **地区差异**：社保基数上下限、费率、公积金比例按 2026 社保年度各市公开口径，跨城对比只看结构，不要当精算结果。
3. **税收政策时点**：综合所得、年终奖单独计税、股权激励单独计税等按 2027-12-31 前有效口径；专项附加扣除按 2023 年提高后的标准。政策调整后请自行复核。

### 建模假设（图上有的地方是「假设」不是「制度」）

- 建筑大工 / 家政 / 日结零工按**未申报**建模（税 0），现实中有代扣与自行申报两种，图里取前者。
- 非全日制小时工**只缴工伤**，这是《社会保险法》对非全日制的最低要求，实践中不少单位连工伤都不缴。
- 灵活就业按**最低基数**自缴（养老 20% + 医保），多数人不会选高档。
- 平台抽成（骑手、网约车、主播）发生在「应发」之前，所以这类案例的倍数是「流水 / 到手」而不是「成本 / 到手」。
- 公积金与年金是**个人资产**，不是税，图中单独回流到个人账户，不计入「被拿走」。

## 本地打开

```bash
# 直接打开
start docs/index.html

# 或改源码后重新打包（需 Node 18+）
node tools/build.mjs        # app/*.js -> dist/labor-income.html
node tools/check.mjs        # 720 组收支闭合校验
```

源码在 `app/`：`data.js`（案例与城市参数）、`engine.js`（税/社保计算）、`sankey.js`（原生 SVG 桑基渲染）、`app.js`（UI 粘合）。

研究底稿在 `research/`：个税规则、社保基数与费率、40 种用工形态、数据口径审查表。
