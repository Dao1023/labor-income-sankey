# 数据口径审查 · 30 个用工案例

审查对象：`app/data.js`（案例数据）、`app/engine.js`（计算逻辑）
对照材料：`research/tax.md`、`research/social-insurance.md`、`research/employment-types.md`（§5.2 八案例、§7 40 行 CSV）
审查日期：2026-11-20 ｜ 计算基准：上海、2026 社保年度、专项附加扣除 3000/月

## 0. 结论摘要

1. **数字大体站得住**：30 个案例的成本倍数与 `employment-types.md` §7 的 `cost_lo/cost_hi` 基本吻合（体制内 2.0×、大厂 1.87×、派遣 1.73×、骑手 1.02×、建筑 1.01×），应发区间也全部落在 CSV 的一线区间内。
2. **有一个必须改的显示错误**：`gov-civil / gov-teacher / gov-doctor / gov-army` 的第 7 槽（10%/5%）被统一标成「经营流水」，但 CSV 里这一槽是「其他（改革性补贴）」。数值没错，**标签错了**，会让公务员看起来有副业流水。
3. **`agency.pay` 方向已基本正确**：派遣管理费、外包服务费走甲方（client）；平台抽成、MCN 分成、包工头抽成、家政中介费走劳动者（worker）。这条是本案最容易搞反的地方，当前设置对。
4. **三处「合法但不高频」的选择需要明说**：建筑/家政/日结按「不申报」建模（税 0）、非全日制只缴工伤（个人养老医疗为 0）、灵活就业按最低基数自缴（20k 收入只扣 2264）。不注明就会被读者当成「制度就是这样」。
5. **一个引擎口径 bug**：平台从业者的 `stats.multiple = 成本 / 到手`，但平台抽成发生在 `gross` 之前，导致网约车显示「1.00×」，而实际上流水里有 45% 被平台和车辆吃掉。应改用 `流水 / 到手`。

## 2. 口径风险（必须让读者看到的 8 件事）

1. **社保基数 ≠ 工资**。工资低于下限（上海 7546）时单位按下限缴，成本倍数反而上升：社工 6000 → 1.68×、国企派遣 6500 → 1.77×。这是「低薪反而更贵」的结构性事实，不是算错。
2. **「按最低基数缴」是常见做法，不是合规做法**。民企/派遣/外包案例用 `min` 建模，图上是事实、法律上是瑕疵；建议在口径弹窗里加一句「员工可主张补缴」。
3. **公积金、年金、养老个人账户都是个人资产**，不是税。图里已经把三条流分开画到账户；文字里要避免把它们算进「被拿走」。
4. **劳务报酬预扣 ≠ 终税**。自由设计师 20000/月：预扣 3200/月（年 38400），年度汇算终税仅 720/年，可退 37680。图上显示的是**预扣现金流**，卡片里给的是**终税**，两者必须同时出现，否则会高估自由职业者负担（tax.md §5.2）。
5. **平台抽成不是税**。网约车流水 15000，平台 25% + 车辆 20% 合计 6750，比个税（75/年）大两个数量级；这条流必须与「国库」分开着色。
6. **灵活就业按最低基数自缴**：自由设计师/远程/个体户按 7546 基数缴 20%+10% = 2264/月，不是按实际收入；基数可在 60%–300% 间自选（social-insurance.md §4.1），选高意味着当期到手更少、退休更多。
7. **年终奖单独计税有断崖**：3.6 万、14.4 万、30 万、42 万、66 万、96 万六个临界点，多发 1 元可能多缴几千。大厂案例的 12% 年终奖正好落在这类区间附近，适合在 tooltip 提示。
8. **「成本倍数」的分母**：本图用 `成本 ÷ 到手现金`（与 §5.2 一致），不是 `成本 ÷ 应发`。两者差 20%–30%，跨案例比较时必须统一；CSV 的 `cost_lo/hi` 未标口径，低薪档（C3 7500）给出的 1.25–1.4 明显低于按 25.76% 单位费率算出的 1.55，疑似按「成本/应发」或未计基数下限。

## 3. 引擎疑似 bug

### 3.1 P0：平台从业者的「成本倍数」口径错

`engine.js` 中 `stats.multiple = cost / net`，`cost` 从 `gross` 起算；但 `agency` 为 `worker` 时，抽成发生在 `gross` 之前（`revenue → agencyDeduct → gross`），所以 `cost ≈ gross`，倍数恒为 1.00–1.03。

复现：

```bash
node -e "const fs=require('fs');const w={};new Function('window',fs.readFileSync('app/data.js','utf8'))(w);new Function('window',fs.readFileSync('app/engine.js','utf8'))(w);const D=w.LABOR_DATA,E=w.LaborEngine;const c=D.cases.find(x=>x.id==='driver');const r=E.compute(c,{gross:c.gross,city:'sh',deductions:3000});console.log('流水',r.revenue,'应发',r.gross,'到手',r.net,'multiple',r.stats.multiple.toFixed(2),'到手/流水',(r.net/r.revenue).toFixed(2))"
```

输出：`流水 15000 应发 8250 到手 8244 multiple 1.00 到手/流水 0.55`

**建议**：`multiple = (agPay==='worker' ? revenue : cost) / net`，或另加 `stats.takeRate = net / revenue`，并在卡片文案上区分「单位成本倍数」与「流水到手率」。否则网约车/主播/骑手会显示「1.0×，没有楔子」，与事实相反。

### 3.2 P1：个体户减半征收的判定条件用错

`engine.js`：

```js
if (c.tax.half && annual <= 2000000) bt *= 0.5;
```

政策是「年**应纳税所得额**不超过 200 万元的部分减半」（2023 年第 12 号，延续至 2027-12-31），判据应是 `taxable` 而不是 `annual`（收入）。当前案例收入都低于 200 万，暂不影响结果；但把滑块拉高或新增高收入案例就会错。

复现：`gross=250000` 的 `remote` 案例，`annual=3,000,000`，`taxable≈2.4M`，代码不减半（正确），但若 `annual=1.9M`、`taxable=1.95M` 就会错误减半；反之 `annual=2.1M`、`taxable=1.8M` 会漏减。

### 3.3 P2：`add()` 丢弃 <0.5 元的节点，可能造成视觉缺口

`buildGraph()` 的 `add()` 在 `value <= 0.5` 时返回 `null`，但 `link()` 仍会 push；`sankey.js` 渲染时按 `byId` 过滤掉指向不存在节点的流，导致该节点的父级「出流和 < 节点值」，流带宽度与节点高度对不上。当前只有北京「+3 元大病」这类极小项会触发，建议统一在 `add()` 里把 <0.5 的金额并入相邻项，或允许 0.5 以下节点存在。

### 3.4 P2：`canEmployer()` 对 `injury` 模式返回 true

非全日制案例打开「单位成本」后，单位支干只有工伤 0.26%（约 20 元），视觉上像一条断掉的细线。建议对 `injury` 也禁用该开关，或把「单位仅缴工伤」做成一句注释而不是一条流。

### 3.5 P2：公积金比例控件与案例默认值不同步

`app.js` 的 `selectCase()` 把 `S.fundRate = null`，但底部 `#fundSeg` 的高亮仍停在 7%。体制内/大厂默认 12% 时，控件显示 7%，用户会以为图算错了。建议 `selectCase()` 里按 `c.si.fund` 反选按钮，`fund=0` 时禁用整组。

## 4. 覆盖缺口（对照 §7 的 40 种形态）

30 个案例与 CSV 40 行主形态一一对应（A1–A4/A6、B1/B2、C1–C4、D1/D2/D4/D5、E1–E4、F0/F1/F3/F5/F6、G1/G2、H1/H5/H6/H7），缺 10 种主形态（另有 18 种 X 系列长尾未进 CSV 主表）。按「是否会改变读者对劳动市场的理解」排序，建议补 5 个：

| 缺失形态 | CSV id | 为什么值得补 |
|---|---|---|
| 专送骑手 | F2 | 与众包骑手形成对照：有加盟商、按最低基数缴、有底薪，成本倍数 1.15–1.3 vs 众包 1.05 |
| 项目外包（B2B） | D3 | 与人力外包（驻场）区分：甲方买的是交付物，承包方员工社保仍按最低 |
| 保安 / 保洁 | F7 | 最低工资档 + 外包，是「有工作但仍无社保」的典型 |
| 管培生 | H2 | 应届生起薪档，公积金 8%，与社招形成对照 |
| 保险代理 / 房产中介 | X1 | 代理制、无底薪、无社保、劳务报酬，是「自雇」里最容易被忽略的一类 |

其余缺口（选调生 A5、代驾 F4、装修工 G3、货运司机 G4、规培生 H3、博士后 H4、辅警 X2、村干部 X3 等）属于长尾，可在「更多形态」里以文字列出，不必都做桑基。

## 5. 复核方法

```bash
# 1) 全量闭合与边界检查（720 组：30 案例 × 6 城 × 4 档收入）
node tools/check.mjs

# 2) 单案例明细
node -e "const fs=require('fs');const w={};new Function('window',fs.readFileSync('app/data.js','utf8'))(w);new Function('window',fs.readFileSync('app/engine.js','utf8'))(w);const D=w.LABOR_DATA,E=w.LaborEngine;const c=D.cases.find(x=>x.id==='gov-civil');const r=E.compute(c,{gross:c.gross,city:'sh',deductions:3000});console.log(JSON.stringify(r,null,1))"
```

**检查结果**：720 组全部通过现金流闭合（最大误差 0.0000 元）、成本闭合、流水闭合、社保基数区间、到手非负；`pensionAcct + pensionPool = pension` 成立。

**未覆盖**：增值税及附加、残保金、工会经费、企业年金单位缴费的税前扣除、年终奖并入综合所得的月度预扣差异、地方性人才补贴。这些在口径弹窗里已声明不计。
